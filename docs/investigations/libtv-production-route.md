# 调研：LibTV 漫剧生成路线与本项目优化方向

> 调研时间：2026-09-09。对应 DEVELOPMENT_RULES 规则 75（Research Before Every Step）。

## 结论

LibTV 的核心竞争力不是单独的“无限画布”，而是把**结构化脚本、可复用角色、参考素材、
模型参数、批量生成和节点依赖**组织成一条可执行、可复用的生产工作流。

本项目已经拥有 Production Graph、持久化 Job、资产版本、能力匹配和阶段暂停，因此不应
先复制一套通用节点编辑器。最短且收益最高的路线是：

1. 先把现有底层状态汇总为“剧集制作台”，让用户一眼看到每个镜头缺什么、卡在哪里；
2. 再把已调通的生成配置保存为工作流模板，实现下一集复用；
3. 逐步增加人物质感、情绪、镜头站位等结构化导演控制；
4. 最后再根据真实使用证据判断是否需要自由节点画布和 CLI 自动化入口。

## 1. LibTV 公开路线

### 1.1 从创意到批量视频

公开资料展示的主链路是：故事创意 / 大纲 → 结构化脚本 → 审核人物、场景、台词、道具 →
补齐角色设定图 → 一键生成镜头提示词 → 自动创建并批量运行视频节点。

这条路线的关键不是“全自动”，而是把人工审核放在昂贵生成之前：用户先检查结构化脚本和
提示词，再执行批量视频，能够减少错误扩散和积分浪费。

### 1.2 资产一致性与直接控制

LibTV 将可复用虚拟角色、画布已有素材与脚本节点连接；人物质感和情绪则通过预设控件、
二维情绪坐标等结构化操作表达，减少用户手写复杂提示词。复杂站位使用 3D 导演台生成
站位参考图，再作为视频节点的输入，而不是继续堆叠自然语言描述。

### 1.3 工作流、模型 Schema 与 Agent

官方 CLI 页面确认 LibTV 将视频、图像和角色能力开放给 AI Agent。公开 CLI 手册进一步
展示了 workspace / project / node / group、素材上传下载、模型 Schema、入边数量限制、
参数校验和 NDJSON 管道。这里最值得借鉴的是“模型自描述参数 + 可执行依赖图”，不是 CLI
命令本身。

## 2. 与当前项目的对照

| 能力 | 当前状态 | 判断 |
|---|---|---|
| 小说 → Story Bible → 剧本 → 分镜 | 已具备 | 主链路完整，无需重建 |
| 角色 / 场景 / 道具引用与外部导入 | 已具备基础能力 | 应强化复用入口和使用范围提示 |
| 持久化 Job、暂停、重试、版本 | 已具备 | 比“一次性批量生成”更安全，应保留 |
| Production Graph | 后端已具备，前端感知弱 | 优先做只读可视化和阻塞说明 |
| 一集生产状态总览 | 分散在多个页面 | 当前最高价值缺口 |
| 可复用工作流模板 | 未形成用户能力 | 适合成为第二优先级 |
| 模型参数 Schema 驱动 UI | 仅 Capability 级别 | 可扩展，但必须渐进，不猜厂商参数 |
| 情绪 / 人像质感 / 站位直接控制 | 未形成结构化控件 | 作为导演控制增强，分阶段验证 |
| 无限节点画布 | 未实现 | 暂不做；现阶段成本高于用户收益 |

## 3. 建议路线

### M1：剧集制作台与准备动作

- 按镜头汇总脚本、角色/场景/道具、提示词、关键帧、视频、审核状态和阻塞原因。
- 提供“准备本集”：只补齐缺失结构和预检，不直接产生付费视频任务。
- 每个异常可跳到对应编辑位置，批量生成前保留阶段确认。

### M2：工作流模板与只读依赖图

- 保存阶段开关、能力要求、模型偏好和生成参数；不保存 API Key，也不绑定不可用模型 ID。
- 模板应用时先生成差异预览，用户确认后才创建 Job。
- 首版只显示当前镜头 / 场景的上游依赖、版本和过期原因，不引入自由拖拽画布。

### M3：结构化导演控制

- 人物质感：用少量语义参数生成可见的 Prompt Patch，并保留原始提示词和版本。
- 情绪控制：先做离散的情绪、强度、目标角色；有模型能力支持后再评估二维连续控件。
- 站位与构图：先支持外部 blocking / pose 参考图和角色映射；真实需求稳定后再考虑 3D 编辑器。

### M4：Schema 驱动参数与自动化入口

- Provider Adapter 返回已验证的参数描述，UI 据此显示选择器 / 滑杆 / 开关并在提交前校验。
- 在现有 API 上提供薄 CLI / Agent 入口，不复制业务逻辑。
- 只有当线性制作台无法表达真实工作流时，才评估节点画布。

## 4. 成功标准

- 用户无需跨页面排查，即可知道一集还缺哪些素材、哪些镜头可生成。
- 批量操作默认先预检，任何付费生成都可见、可取消、可重试。
- 同一套制作配置可应用到下一集，但不会携带密钥或失效模型引用。
- 所有结构化控制都生成可查看、可修改、可版本化的最终请求，不形成黑箱。
- 不破坏现有黄金路径，不削弱用户手动选模和阶段暂停能力。
