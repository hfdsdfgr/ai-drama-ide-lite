# Phase 24 M2 实施报告

日期：2026-09-11。状态：完成。

## 用户获得的能力

1. 每一集都有独立制作配置，可选择分镜、关键帧和视频阶段的开关、模型、Capability、比例、规格与时长策略。
2. 调通的配置可以保存为当前项目模板，并可重命名、更新或删除；删除模板不会影响已应用到剧集的配置。
3. 使用模板前展示逐字段差异，默认不选择任何项。用户只应用明确勾选的配置，失效模型会显示同能力候选，不会静默替换。
4. “保存配置 / 管理模板 / 比较模板”均不创建 Job。只有“开始制作本集”通过完整预检后创建一个剧集 Pipeline Job。
5. 剧集 Pipeline 只处理目标集，从已有剧本依次执行分镜、关键帧、视频；小说分析、剧本生成和共享资产保持只读前置条件。
6. 用户可从制作台查看单镜头或整场景的实际版本依赖，并跳到对应资产或分镜。历史固定、过期、损坏和旧数据未记录来源都有明确状态。

## 完整 AI 漫剧链路中的作用

M1 解决“这一集缺什么”，M2 解决“这一集按什么配置生产、能否安全复用、结果用了什么来源”。这使按集批量生成从项目级黑箱操作变为可预检、可复用、可暂停恢复且可追溯的生产单元，并为后续导演控制提供稳定的配置和版本基础。

## 实现边界

- 模板只保存在所属项目，不跨项目共享。
- 模板不保存 Prompt、资产、参考版本、生成结果、文件路径、Job 状态或 API Key。
- 启动后使用不可变配置快照；之后修改模板、剧集配置或全局默认模型，不影响该次运行。
- 当前工作流不加入音频参数；视频阶段明确以 `with_audio=false` 提交。
- 依赖视图是只读线性关系，不引入画布或图编辑依赖。
